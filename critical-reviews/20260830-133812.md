## Scope and decision

This pass uses Pyright as a fault-finding instrument across the shipped Python surface. The baseline reports 160 errors across 28 files. Most diagnostics cluster around deliberately normalized identifier DTOs, subprocess overloads, and SQLite row-shape annotations; the raw count is therefore not accepted as proof of 160 runtime defects.

The decision is evidence-first patching. A finding is accepted only when the reported path is reachable at runtime, weakens an exported contract, or blocks a small honest type-checking boundary. Broad ignores, casts that only silence the checker, and a nominally green configuration that excludes consequential code are out of scope.

## Findings

### Finding 1: low, receipt output type excludes a valid durable target kind

Status: repaired; proportional verification pending.

`TargetKind.SYSTEM` is a valid version 1 contract value. Direct durable callers can submit such a scope, the coordinator can retain a rejected disposition for it, and the intent view deliberately renders that durable evidence. `IntentScopeView.target_kind` nevertheless claimed only `configured_scope` or `object`, while composition emitted the third value. This did not corrupt runtime JSON, but it made the presentation contract false and encouraged unsafe exhaustiveness assumptions in typed consumers.

Repair: widen only the receipt-output model to include `system`; keep `RefreshRequest` and the browser form allowlist restricted to the two supported interactive targets. A direct durable-intent regression proves the valid unsupported target survives into the receipt view without making it an accepted browser input. The focused test passes and the associated Pyright diagnostic is removed.

### Finding 2: low, duplicate-coverage key annotation contradicts runtime identity

Status: repaired; proportional verification pending.

The duplicate-coverage set was declared as seven mandatory strings, while `_scope_columns` has always produced eight values and permits an absent capability key. Runtime duplicate detection remained correct because Python hashes the actual tuple, but the annotation contradicted the same identity used for lookup and insertion.

Repair: define one shared eight-field key type, including the optional capability, use it for producer and set, and explicitly stringify the post-init-normalized system ID. Coverage-focused ingestion tests pass and both the false return mismatch and set insertion diagnostics are gone.

### Finding 3: medium, Windows ownership setup can leak a suspended child

Status: repaired; proportional verification pending.

Windows starts the CLI suspended so it can enter a kill-on-close Job Object before executing. `_ProcessTree` obtained the native process handle through private asyncio transport and `Popen` attributes, while `_execute` cleaned up only `OSError`. An `AttributeError` or another compatibility failure could therefore bypass kill/wait and leave a suspended child behind.

Repair: open the documented Win32 process handle from the public PID with only `PROCESS_TERMINATE | PROCESS_SET_QUOTA`, assign it to the Job Object, and close the temporary handle. Every exception during ownership setup now kills and awaits the child; cancellation and other control exceptions retain their original semantics. A non-`OSError` regression proves kill, wait, controlled error mapping, and work-directory cleanup. All 151 adapter tests, including real Windows descendant ownership, pass.

### Finding 4: low, profile parser disables inheritance through an unsupported type value

Status: repaired; proportional verification pending.

The selected-profile security boundary intentionally treats `[DEFAULT]` as an ordinary Databricks profile and forbids cross-profile inheritance. It achieved this with `ConfigParser(default_section=None)`, which current CPython accepts even though the public contract requires a string, and assigned `optionxform` dynamically despite the documented subclass hook.

Repair: a case-sensitive parser subclass uses a string sentinel that valid profile names cannot contain; NUL-bearing configuration is rejected before parsing. Parse failures still raise outside the exception context so secret-bearing source lines cannot survive in chained traceback state. Existing no-inheritance/case tests and a new NUL regression pass.

### Finding 5: low, expired/live linked-scope partition is quadratic

Status: repaired; proportional verification pending.

The action-deadline guard built a tuple of expired scope IDs and then classified every linked scope through linear tuple membership. A heavily coalesced action therefore performed quadratic local work at its deadline.

Repair: parse each nullable expiry once and partition linked scope IDs into expired/live lists in one pass. Mixed expired/live guard regressions pass. Related lease, facet, and relationship paths now parse durable timestamps once and fail explicitly on impossible missing schema values instead of relying on repeated-call narrowing.
