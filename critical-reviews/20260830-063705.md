## Finding 1: medium, invalid remote configuration blocks local recovery commands

Confidence: high  
Evidence quality: A

Status: closed. `load_app_settings()` performs one bounded TOML read, top-level allowlisting, full `[app]` allowlisting, and complete local settings validation while ignoring only Databricks semantics. Only backup/list/retire/unretire use it; initialization, doctor, workers, and serve retain full validation. Independent patch review found no high or medium defect.

`main()` loads complete `ProjectSettings` before `backup`, `authority-list`, `authority-retire`, or `authority-unretire`. Those commands use only `app.database_path`, but any invalid Databricks profile, workspace root, fingerprint, duplicate identity, or newly unknown remote setting prevents them from reaching local SQLite.

Reproduction against the verified migration-0021 local database used a syntactically valid TOML file with the correct `[app].database_path` and one Databricks entry missing `profile`. Both commands failed before database access:

```text
authority-list-exit=2
backup-exit=2
backup-exists=False
error: databricks[0].profile must be text
```

This violates the intended recovery boundary: a broken remote declaration can block the no-overwrite backup needed before repair or upgrade, and can block inspection or retirement of already persisted authorities. Editing the remote array away is a workaround, but it is undocumented and makes a local safety operation depend on manual configuration surgery.

Repair shape: add a bounded app-only configuration loader that still parses TOML, rejects unknown top-level and `[app]` keys, and fully validates local paths and limits while ignoring the semantics of the `databricks` value. Use it only for backup and authority inventory/retirement commands. Stateful initialization, doctor, workers, and serve must retain full validation.

Verification: initialize valid state, replace the remote array with syntactically valid but semantically invalid content, then prove backup, inventory, retire, and unretire operate on the intended database without reconciling remote desired state. Malformed TOML, invalid app settings, and unknown top-level settings must still fail before filesystem or SQLite mutation.

## Finding 2: high, profile parser divergence can cross credentials and routes

Confidence: high  
Evidence quality: A

Status: closed. `DEFAULT` is an ordinary explicit profile, only own case-sensitive selected-section keys are retained, and a global physical-line preflight rejects quoted/noncanonical keys, valueless or multiline forms, backticks/triple quotes, and continuation before section selection or comment removal. Double/backtick host and all selector variants, duplicate collisions, DEFAULT crossover, selected and unselected continuation, and worker A→B→A paths are independently clear.

Rookery parses `.databrickscfg` with Python `ConfigParser`, where `[DEFAULT]` values are inherited by every named section, then serializes `parser.items(profile)`. Databricks CLI 0.298 uses SDK-Go 0.128 and go-ini section `KeysHash()`, which returns only the selected section's own keys. Rookery therefore changes the selected profile's authentication semantics.

Reproduction placed a synthetic token under `[DEFAULT]`, a different host plus `auth_type = pat` under `[PRIMARY]`, and compared `databricks auth describe --profile PRIMARY` against the generated snapshot. The source correctly reported that a token was required. The snapshot contained the inherited token and attempted an authenticated request to the PRIMARY host.

This can send profile A's credential to profile B's host without same-user compromise. It also expands crash-retained secret scope beyond the selected profile.

Repair shape: parse `DEFAULT` as an ordinary explicit profile, preserve case-sensitive own-section keys, match the pinned CLI's space-before-inline-comment behavior, reject unsupported ambiguous INI forms, and serialize only the selected section. Reserved `__settings__` is not a profile. Authority lookup and snapshot generation must use the same own-section mapping.

Verification: DEFAULT credentials never appear in a named snapshot; a named profile missing a token stays missing it; DEFAULT and named profile authorities remain independent; key case and inline comments match CLI behavior; selector A→B→A and worker provenance tests remain green.

## Finding 3: medium, `skip_verify` defeats route identity

Confidence: high  
Evidence quality: A

Status: closed. Truthy `skip_verify` variants are rejected under DEFAULT and named profiles; malformed booleans fail closed and false variants remain compatible. Global canonical-key validation also rejects quoted/backtick TLS keys before policy checks or snapshot creation.

The current parser accepts an HTTPS host and copies `skip_verify = true` into the child snapshot. The pinned SDK maps that setting to TLS certificate-verification bypass. A network attacker can then impersonate the fingerprinted hostname, receive credentials, and return forged metadata despite the configured route digest.

Repair shape: parse the selected profile's `skip_verify` with the pinned CLI's accepted boolean vocabulary and reject every truthy value before fingerprint generation or process creation. False values remain compatible; malformed values fail closed.

Verification: cover true/false variants for DEFAULT and named profiles, assert no snapshot or runner call after truthy rejection, and preserve normal certificate-verified execution.

## Finding 4: medium, continuation and mixed-comment syntax changes selected credentials

Confidence: high  
Evidence quality: A

Status: closed. Raw global preflight detects continuation before comment handling and before deciding which physical section is selected. Selected comments apply the pinned hash-before-semicolon precedence. Retained comment fragments use CLI-recognized backtick shielding when representable and otherwise fail closed. Real CLI probes reproduced equivalent source/snapshot credential values and rejected both section-consuming continuation orderings.

The pinned CLI supports trailing-backslash continuation and gives ` #` precedence over ` ;` when both inline markers appear. Python `ConfigParser` does neither identically. In a reproduced profile, CLI consumed the following `token` line into a continued `workspace_id` and made no authenticated request, while Rookery emitted a separate token and its child attempted authentication. For `token = alpha ;retained # discarded`, CLI retained `alpha ;retained` while Rookery retained only `alpha`.

Repair shape: preflight the raw selected section and reject continuation, quoted keys, valueless keys, and unsupported multiline/quoted forms. Apply the pinned CLI's explicit hash-before-semicolon inline-comment precedence before semantic parsing. Restrict keys to a canonical unquoted vocabulary so route and TLS policy checks cannot be bypassed through key normalization.

Verification: source-versus-snapshot CLI probes for continuation and mixed comments, double/backtick route-selector and `skip_verify` rejection, duplicate collision rejection, and preserved ordinary token values.
