## Scope and decision

This pass reviews the installed Python package as an extension surface rather than only as the bundled application. It checks exported DTOs, enums, protocols, constructors, canonical serialization, migrations, architecture claims, and checkout-free wheel behavior after explicit time provenance was added to the v1 observation contract.

The decision is patch-after-review. Backward-compatible defaults must preserve old callers and stored digests; new semantics must be explicit rather than inferred; exported protocol signatures must match concrete implementations; package assets and documentation must let wheel consumers understand the implemented boundary; and deferred extension points must not be presented as stable current APIs.

## Findings

### Finding 1: medium, additive provenance broke positional and JSON v1 compatibility

Status: closed.

`ObservationBatch.observed_at_is_local` was inserted before `contract_version`. Existing positional callers supplying the v1 version as the twelfth argument therefore bound `"1"` to the new boolean and failed validation. Default `to_dict()` also gained `observed_at_is_local: false`, which could break strict v1 JSON consumers even though canonical digest bytes explicitly omitted it.

Repair: append the new field after the existing v1 positional surface, and override `ObservationBatch.to_dict()` to omit the false default while emitting explicit true provenance. A regression constructs the complete old positional signature, checks the version/default, proves old JSON shape, and proves local-time JSON remains explicit.

### Finding 2: medium, dirty verification deletes the last clean release manifest

Status: closed.

`publish_release_evidence()` wrote `dist/runtime-constraints.txt` and unlinked every `rookery-*-SHA256SUMS.txt` before running `git status`. On an ordinary dirty local checkout it then returned `None`, leaving no old manifest and no replacement. CI dirtiness similarly raised only after destructive mutation.

Repair: complete Git availability, all-untracked cleanliness, HEAD, and `GITHUB_SHA` checks before any `dist/` mutation. Write the new manifest before removing stale peers. A unit regression snapshots every distribution filename and byte, simulates dirty status, and requires byte-for-byte preservation.

### Finding 3: low, installed CLI help omits the product/package identity mapping

Status: closed.

README explicitly states that Rookery is distributed as `async-api-view`, but the installed command described only a generic state viewer. This is not a runtime failure; it creates avoidable support/recovery ambiguity when package, command, logs, database, and checksum names differ.

Repair: make CLI help name both Rookery and the compatibility command, and require the mapping in installed-wheel smoke.
