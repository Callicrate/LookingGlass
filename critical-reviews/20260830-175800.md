## Scope and decision

This pass reviews the local operator's failure path from installed CLI help through configuration, initialization, doctor, one-shot work, serve startup, authority commands, backup, and the browser recovery shell. It tests whether expected local failures are redacted, traceback-free, correctly classified, actionable, and consistent with the documented command surface.

Remote Databricks behavior and already-closed storage/migration semantics are outside this pass except where their controlled errors cross the operator boundary. Live credentials and a remote profile will not be guessed.

## Findings

### F1 — Medium: expected CLI errors can inject terminal controls and local paths into logs

`main()` logs caught `ConfigError`, `RuntimeError`, `ValueError`, and `OSError` text directly. A missing `--config` value containing a newline, ANSI escape, and token-shaped segment produced a two-line log carrying the control sequence, the opaque value, and an absolute Windows home path. The same boundary receives output/backup paths and lower-layer runtime errors.

Expected errors need one bounded operator-diagnostic sanitizer before logging. The existing adapter diagnostic sanitizer already removes controls, token/profile values, and Windows/POSIX paths and can be reused without exposing raw remote output.

### F2 — Medium: operator interruption escapes the controlled CLI boundary

When `doctor` or `run-once` is interrupted, `asyncio.run()` re-raises `KeyboardInterrupt`. Because `main()` does not catch it, `python -m async_api_view` can print a traceback instead of reporting deliberate cancellation and returning the conventional exit code 130. `run-once` still closes its store through `finally`, but the operator-facing result violates the controlled-failure contract.

Add an explicit `KeyboardInterrupt` boundary after command dispatch, log one sanitized cancellation message, and return 130. Preserve argparse's own usage exit behavior outside that boundary.

### F3 — Medium: outage-event persistence failure logs the raw exception traceback

Runtime supervision intentionally persists only a closed component/type summary, but if that persistence call itself fails, `_record_background_failure()` uses `logger.exception()`. The exception message and traceback therefore cross the process log even though the surrounding message calls the event redacted. A storage error can contain path or injected diagnostic material and this path represents an expected degraded-state failure, not a debugging-only crash.

Log one closed component-scoped sentence without exception detail or traceback. A direct regression injects token, control, and home-path material into the persistence exception and proves none reaches the log.

### F4 — Medium: unexpected request failures bypass the recovery shell and security headers

A direct failure from local-session authentication returned Starlette's plain-text `500 Internal Server Error` with no CSP, `Cache-Control`, frame denial, or accessible recovery navigation. Expected backend route failures are individually translated, but middleware, template, and other unexpected local failures sit outside the normal response-header middleware as they unwind to `ServerErrorMiddleware`.

Register one closed generic exception response for HTML and API requests, log no exception detail, render the existing accessible error shell, and explicitly apply the security header set inside that handler. The regression injects secret/path/control text from authorization and requires the secure 500 shell without leakage.

### F5 — Medium: argparse can echo hostile usage values before command dispatch

Argument parsing intentionally remains outside the runtime exception boundary so usage errors preserve argparse exit 2, but argparse's default `error()` includes invalid choices and unknown arguments verbatim. An ANSI/bidi/token-shaped `--log-level` value therefore bypasses the new operator sanitizer.

Use a small `ArgumentParser` subclass that preserves canonical usage output and `SystemExit(2)` while sanitizing only the dynamic error sentence. A regression requires no stdout, no hostile value or controls, and an actionable usage line.

### F6 — Medium: authority inventory can traceback on contained row corruption

Two independent probes reproduced uncaught `TypeError`: a BLOB terminal action timestamp reached `_dt()`, and a numeric JSON authority fingerprint reached CLI slicing. Both stores remained recognized and foreign-key clean, but `authority-list` exited through a full traceback.

Read authority systems, identities, bindings, and activity only through the current readable views; make timestamp conversion reject non-text with a controlled `ValueError`; and retain the authority row with `legacy-unverified` metadata when its binding is isolated. The regression corrupts binding JSON and requires successful contained stdout with no traceback.

### F7 — Medium: usage and operational failures share exit 2

Argparse misuse and configuration/storage/dependency failures all returned 2, forcing automation to parse text. Uvicorn startup also used 3, colliding with `run-once` bounded incompletion.

Reserve exit 2 for argparse usage, use exit 1 for controlled runtime failure, retain exit 3 only for bounded `run-once` work, and retain 130 for interruption. The README and installed smoke are updated to this explicit matrix.

### F8 — Medium: authority inventory is suppressible stderr logging

`authority-list` emitted primary records through `logger.info`. Redirection left stdout empty, and `--log-level WARNING` suppressed a healthy non-empty inventory entirely.

Write sanitized inventory records directly to stdout independent of log level; keep informational/error diagnostics on stderr. Healthy and corruption-contained regressions verify the stream split.

### F9 — Medium: Uvicorn startup failure leaks a traceback, collides with exit 3, and consumes activation early

An application lifespan startup failure caused Uvicorn to log its dependency traceback, raise `SystemExit(3)`, and do so after Rookery had already consumed and printed the one-time activation capability.

Use a small server subclass to disclose activation only after Uvicorn and application startup succeed. Scope a filter to Uvicorn's error logger during server ownership, collapse lifespan traceback records to a closed sentence, translate Uvicorn startup exit 3 to Rookery runtime failure 1, and preserve listener/store cleanup.

### F10 — Medium: disconnected dashboard makes verified empty/clear claims

When dashboard loading failed or no backend was supplied, the template rendered “No alertable failures recorded,” “No systems configured,” “No cached objects,” zero counts, and “Refresh unavailable” beside the disconnected warning. Those are conclusions about data that was never read.

Render a distinct unavailable trust boundary, suppress all counts and inventory/alert/refresh empty states while disconnected, and state that no cached-state conclusion is available. Exception-backed and default-backend regressions protect the distinction; healthy loaded-empty behavior remains unchanged.

### F11 — Medium: authorization failure recovery links loop back to the same 500

The generic secure 500 shell initially linked both “Try again” and “Return to dashboard” to `/`, which necessarily re-entered the failing authentication middleware. The public `/bootstrap` route remained available but unreachable from the shell.

Handle authorization-construction failure at its middleware boundary, render the accessible secure shell with only `/bootstrap` recovery, and verify that rendered destination returns 200. API callers receive a closed JSON error.

### F12 — Medium: expired-session restart copy can discard the active configuration

Literal `async-api-view serve` recovery copy drops an operator's non-default `--config` and other options, potentially failing or opening a different local store.

Tell the operator to rerun the same `async-api-view … serve` invocation while preserving `--config` and all options. Both middleware and static bootstrap recovery tests require this wording.

### F13 — Low: installed help smoke omitted two commands

The source/wheel command vocabularies matched, but installed smoke asserted only nine names. Add `init` and `run-once` so all 11 commands are protected.

### F14 — Medium: Uvicorn access logs expose untrusted request targets

Production-wrapper probes showed unauthenticated paths/query strings containing standalone token text, a `DATABRICKS_TOKEN` assignment, and a home path verbatim in `uvicorn.access`. The scoped error filter cannot affect access records.

Disable Uvicorn access logging for this local, activation-capability-bearing process. Rookery's closed operational events and component logs remain the supported diagnostics; raw HTTP request targets are not required.

### F15 — Medium: standalone tokens and prefixed JSON credentials evade redaction

Assignment-based redaction missed a standalone GitHub-token shape and JSON keys such as `DATABRICKS_TOKEN`. Both crossed missing-config stderr unchanged.

Extend the shared sanitizer with narrow standalone GitHub/Databricks/AWS/JWT signatures and the same prefixed JSON credential-key grammar used by durable storage. Runtime and adapter regressions prove the opaque values are removed.

### F16 — Medium: single-quoted/escaped secrets and `/root` paths evade redaction

A later adversarial pass reproduced single-quoted credential mappings, escaped JSON representations with a visible suffix, and `/root/...` paths crossing argparse stderr.

Normalize escaped quote representations before matching, accept single or double credential mapping quotes, consume malformed quoted values through a safe delimiter, and include `/root` in the bounded local-path family. Direct adapter and CLI regressions cover all three forms.

### F17 — Medium: backward retirement time can erase verified inventory metadata

Retirement accepted a caller timestamp earlier than configuration record creation. The updates then failed readable-view timestamp ordering, so a verified retired authority appeared as `legacy / unknown / legacy-unverified` even though its durable identity remained intact.

Derive one effective retirement timestamp as the maximum of requested time and every canonical affected system/binding/capability/scope/action/prior-retirement timestamp. Use it for cancellation and record updates in the same transaction. The existing backward-time lifecycle regression now requires config ID, root, and fingerprint to remain stable.
