## Scope and decision

This pass asks whether the committed Rookery baseline can be changed and operated safely after the standalone release closure. It reviews maintainability seams, residual runtime/storage failure semantics, and the browser/operator surface. Live Databricks inventory, deferred product expansion, and the already-closed standalone installer chain are out of scope unless a distinct regression is reproduced.

The decision is patch-after-review: retain only evidence-backed findings, repair accepted defects autonomously, verify the affected contract and full supported gates, obtain independent re-review, then close this ledger.

- Baseline release verifier: 90 sdist entries, 66 wheel entries, 34 installed runtime assets, with a checksum manifest bound to clean commit `d83e4009f72375f94eaf7e79bfc654384c72d822`.
- Latest full gates before this pass: Windows 598 passed / 8 expected skips; Ubuntu/WSL 600 passed / 6 expected skips.
- Complexity triage: 34 functions exceed cyclomatic complexity 10. Highest production values are `web.app.create_app` 36, `SQLiteStore.ingest` 31, `_evaluate_action_guard` 27, and `DatabricksWorker.process` 24. These are review targets, not defects by themselves.
- Broad exception triage found catches at runtime supervision, route rendering, worker ingestion, and storage cleanup boundaries; each requires contract-specific adjudication rather than blanket removal.
- Deterministic browser boundary probes reproduced bootstrap redemption at its exact expiry instant and plaintext 500 responses for malformed bracketed `Origin` or `Referer` values. Neither allowed unauthorized work, so both are low severity; the accepted repair changes exact expiry to fail closed and converts parser errors to ordinary same-origin rejection.
- Coordinator/store inspection reproduced a finalization race: a request can expire after its scope lease is issued but before satisfaction, deferral, rejection, coalescing, or admission is recorded. Final transactions validated only `leased_until`, so an expired request could receive a non-expired receipt and a new action could be created. The later action guard still prevented remote dispatch, limiting severity but not repairing durable truth.
- Independent lifecycle review reproduced two distinct supervisor tasks after calling `ApplicationRuntime.start()` twice. `stop()` owned only the second task and closed SQLite while the first remained blocked in compatibility startup. The normal FastAPI lifespan calls start once, but the public runtime lifecycle did not enforce that assumption.
- Independent worker review injected `sqlite3.OperationalError` at the canonical ingestion port. The broad action handler recorded `unknown_adapter_failure` and returned normally, leaving refresh controls enabled even though local canonical writes were unavailable. Contract-level ingestion rejection remained correctly action-scoped.
- Independent storage review loaded 2,000 malformed ready actions. One `lease_next()` call quarantined every row in a single immediate transaction, taking 2.082 seconds and preventing an event-loop yield or competing SQLite writer. Due/retry promotion was already capped, but malformed-row cleanup was not.
- Independent recovery review inserted an integrity-clean SQLite `REAL Infinity` attempt ordinal. `lease_next()` converted the aggregate to `int`, raised `OverflowError`, rolled the transaction back, and selected the same ready action forever with no quarantine alert. DTO validation protects new writes, but retained/manual/legacy corruption remained able to wedge the worker.
- The same review proved a future caller timestamp passed to `authorize_start()` was persisted as `started_at` and projected into durable cooldown state. A value 30 days ahead deferred the next refresh for 30 days even though lease, deadline, and policy authority otherwise used the injected store clock.
- An isolated WSL full gate then reproduced a 0.86-second wall-clock regression between local root creation and worker observation. Existing roots with no prior `last_seen_at` accepted the older timestamp, created `first_seen_at > last_seen_at`, and rejected every relationship in the supported 10,000-child collection.

## Findings

### Finding 1: low, browser capability edge cases do not fail closed cleanly

Status: closed.

At `web/auth.py:101`, bootstrap redemption used a strict `>` expiry check while every session and durable deadline boundary uses `>=`. A deterministic clock accepted the token at exactly its stated expiry. At `web/app.py:86`, malformed bracketed URL syntax from `Origin` or `Referer` allowed `urlsplit()` to raise `ValueError`, producing plaintext 500 without the normal CSP or no-store headers.

There is no demonstrated authorization bypass or secret disclosure: exact monotonic equality is a narrow timing edge, malformed headers are not emitted by normal browsers, and the backend was not reached. The defects are retained because they are deterministic boundary-contract violations with a minimal repair.

Repair: make token expiry an exclusive upper bound and treat URL parse failure as a same-origin mismatch. Regressions require exact-expiry rejection plus malformed Origin/Referer 403 responses with security headers and zero backend submissions.

### Finding 2: medium, intent expiry is not fenced at final coordinator disposition

Status: closed.

`DurableCoordinator.run_once` samples store time before leasing and performs several local decisions before finalization. `SQLiteStore.set_intent_scope_disposition` and `admit_or_coalesce` atomically revalidated the coordinator lease but did not revalidate the parent intent's `expires_at`. A deterministic clock advancing to exact request expiry while the scope lease remained current produced a post-expiry disposition or action admission. Remote dispatch remained protected by the action guard, but durable intent truth and avoidable work were wrong.

Repair: sample store time inside every final disposition/admission transaction, make request expiry override non-expired outcomes, and return the effective state so the coordinator reports `expired`. Regressions cover exact expiry during integrated admission and every direct terminal/deferred disposition.

### Finding 3: medium, repeated runtime start orphans the first supervisor

Status: closed.

`ApplicationRuntime.start()` replaced its stop event, wake event, and background-task handle without checking current lifecycle state. A second call started another supervisor; `stop()` cancelled only the replacement and then closed SQLite, leaving the first task alive and able to resume against a closed store. The application lifespan itself invokes start once, so the defect requires programmatic lifecycle misuse, but the resource-ownership invariant was not enforced.

Repair: make one runtime instance single-use, reject every repeated start, keep the original task handle, and make stop idempotent. A blocked compatibility-start regression requires the repeated call to fail and the sole owned task to be cancelled and awaited before storage closes.

### Finding 4: medium, canonical-ingestion outages leave refresh controls enabled

Status: closed after residual recovery repair.

Unexpected exceptions from `ObservationIngestionPort.ingest()` entered the worker's generic action-failure handler. The action was marked with `unknown_adapter_failure`, `run_once()` returned normally, and the runtime supervisor continued to advertise refresh availability even though its canonical write boundary was failing. This differs from an explicit `IngestionStatus.REJECTED`, which is a valid action-scoped contract result.

Repair: preserve `ActionLeaseLost` as a stale-work return, but wrap every other unexpected ingestion exception as `LifecyclePersistenceFailure`. The existing composed lifecycle-outage regression now includes the store `ingest` method and requires unavailable controls, one redacted outage event, and safe shutdown.

Initial re-review found that CLI doctor plus an empty worker iteration cleared this outage before canonical persistence had been retried, then emitted another first-failure event when the lease later recovered. Recovery now retains a required ingestion generation and clears degradation only after a later canonical ingestion call succeeds. A persistent-failure regression holds controls unavailable with one event, restores ingestion, advances through lease recovery, and then requires health recovery.

### Finding 5: medium, malformed ready actions bypass the queue work bound

Status: closed.

`SQLiteStore.lease_next()` looped until it found a valid ready action or exhausted the entire ready queue. Each malformed action was safely and idempotently terminalized, but 2,000 malformed rows were processed inside one immediate transaction. The call held the same-process store lock and SQLite write ownership for 2.082 seconds. This is distinct from the previously capped due/retry promotion path.

Repair: cap malformed-action terminalization at 100 rows per claim and return control to the background loop before continuing. A regression creates more than one cap of malformed actions, proves the first claim changes exactly the cap, drains the remainder on a later claim, and retains one alert per action.

### Finding 6: medium, malformed attempt ordinals permanently wedge queue leasing

Status: closed.

SQLite integer affinity does not prevent retained values such as real infinity, exponent text, zero, or negative ordinals. `lease_next()` previously calculated `int(MAX(ordinal) + 1)` after marking the action leased. Conversion failure rolled back the transaction, so the same ready action won every retry and no alert was retained.

Repair: summarize and validate attempt ordinal storage classes and bounds before leasing. Invalid history terminalizes the owning action through the same bounded quarantine path and selection continues to healthy work. Regressions cover infinity, exponent text, zero, and negative values.

### Finding 7: medium, caller start time remains durable cooldown authority

Status: closed.

Final authorization sampled store time for lease validity but persisted caller-provided `now` into `adapter_actions.started_at`. Migration 0018 projects that field into cooldown authority, contradicting the closed contract that caller timestamps are record-only. A 30-day future caller value deferred later work until that future timestamp plus the interval.

Repair: retain caller timestamps only for interface compatibility and persist the final transaction's store-owned time as semantic `started_at` in both `authorize_start()` and legacy `mark_running()`. A future-caller regression requires running lease renewal and cooldown start to use the injected store clock.

### Finding 8: medium, an earlier first observation violates object time ordering

Status: closed.

A configured root can be created immediately before a remote observation is timestamped. When the process wall clock steps backward, or when delayed evidence legitimately carries an earlier observation time, the existing object has `last_seen_at = NULL` and accepts that timestamp. The update previously left `first_seen_at` at the later local-creation time, so DTO reconstruction rejected `last_seen_at < first_seen_at`. A natural WSL clock step made all 10,000 relationships partial with this error.

Repair: whenever an existing object accepts its first or later present observation, set `first_seen_at` to the lexical minimum of its canonical UTC value and the accepted observation, in both canonical-ID and external-identity paths. Deterministic regressions cover both locators with observation time one second before local creation.

## Adjudicated candidates

- Durable history and backup growth remain an explicit documented operating limitation, and no automatic scheduler currently creates ambient growth. The capacity/headroom concern is not misrepresented by the current product, so it is not merged as another defect here. It is elevated into the next autonomous review because a pre-exhaustion guard can still materially improve operation.
- One Windows verifier run received transient access denial during a temporary environment rename. Two immediate Windows reruns and the final Windows/WSL package gates passed. The isolated failure is retained as a watch item, not promoted without a repeatable mechanism.
- Cyclomatic complexity identified review targets but did not establish defects on its own. No score-only finding was manufactured.
