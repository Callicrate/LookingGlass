## Findings

### F1 — Medium: corrupted-state `serve` tests depend on global port 8765

With an unrelated synthetic local server on 127.0.0.1:8765, the byte-corrupt and schema-corrupt `serve` cases failed on listener reservation before reaching their intended immutable SQLite boundary. Production ordering was correct; the tests were false-red and their asserted diagnostic became environment-dependent.

Repair: each affected `serve` case reserves its own real IPv4+IPv6 ephemeral listener pair and monkeypatches only the reservation function to hand those exact owned sockets into normal command flow. The sockets still close through production cleanup. With 8765 deliberately occupied, all nine affected command cases pass.

### F2 — Medium: local Windows/WSL instructions permit one shared `.venv` and coverage file

Running `uv` concurrently from Windows and WSL in one checkout let the Linux invocation treat the Windows `.venv` as incompatible and partially remove it while Windows tests were active. The suite happened to finish, but its post-test coverage executable was damaged; shared coverage output can also race.

Repair: prohibit concurrent complete gates in one worktree because coverage JSON, constraints, caches, and `dist/` remain shared. Require serialization or separate native worktrees; separate platform-native environments and coverage/report names are sufficient only for disjoint test portions that do not build or verify distributions. CI already runs on separate machines.

### F3 — Medium: untracked generated source can define its own package authority

The verifier used `git ls-files --cached --others` for expected sdist files and recursively scanned `src` for expected wheel files/assets. An interrupted generator leaving unignored `src/async_api_view/generated.py` could therefore be included by Hatch and accepted because the same untracked file defined the expected manifest; local verification printed “Verified” and only deferred clean-commit publication.

Repair: derive sdist, wheel source, and runtime asset authority from tracked files only. Reject any untracked, non-excluded release source before opening archives or executing installed artifacts. Workspace-only progress/review files remain explicitly excluded. A regression proves untracked package source is rejected while excluded progress is ignored.

### F4 — Medium: verified bytes are not bound through manifest publication

Archives were verified by path, then reopened after Git checks to compute manifest hashes. A concurrent writer replacing the wheel during `rev-parse` caused unverified replacement bytes to receive the clean manifest. Constraints and manifest writes were also non-atomic, so interruption could leave mutated constraints, a partial new manifest, and stale evidence together.

Repair: retain exact source/wheel/constraints byte snapshots after all smoke checks; recompare current files immediately before publication; compute hashes only from retained verified bytes; stage complete constraints/manifest files in a temporary distribution subdirectory; remove stale manifests before promotion; and use atomic replacements. Interruption leaves either no new manifest or one complete manifest whose hashes cannot authenticate replacement bytes.

### F5 — Medium: verifier timeout/interruption owns only parent subprocesses

Plain `subprocess.run` kills its immediate `uv`/Python parent but does not own build-backend or helper descendants. A timeout or interruption can leave a child retaining temporary-environment handles, especially on Windows.

Repair: route all 27 verifier commands through one structured runner. POSIX starts a new session and kills the process group. Windows starts suspended, assigns a kill-on-close Job Object before resume, terminates and drains the job on normal completion, timeout, interruption, or error, then bounds parent wait. A real delayed-descendant timeout regression proves no marker can be written after return; both platform full verifiers pass.

### F6 — Environment-level: wrapper interruption can outlive `uv run` children

The agent shell's Ctrl+C stopped three `uv run` wrappers but left their synthetic Python servers on ports 8765, 8891, and 8892. Each exact PID/command line was resolved and terminated. This did not traverse Rookery's production process owner or the new verifier runner; the lesson is to invoke long-running QA interpreters directly or verify descendant cleanup rather than treating wrapper-session exit as proof.
