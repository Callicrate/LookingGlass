## Scope and decision

This pass reviews two linked questions. First, can one malformed connection binding, capability binding, configured scope, or system identity hide otherwise healthy cached state? Second, do migration-0024 readable views preserve bounded indexed pagination and avoid full-history scans?

Authority corruption must never produce an enabled refresh option, verified label, target, capability, or dispatch path. Cached facts and healthy authorities should remain readable when the corrupt record can be isolated explicitly. Query-local validation must be driven by existing cursor/target indexes; a safety view that turns every page into an unbounded scan is not acceptable.

## Findings

### Finding 1: high, corrupt authority rows collapse cache or remain refreshable

Status: closed.

Malformed binding/capability JSON or configured-scope timestamps collapsed the dashboard and unrelated object pages. Syntactically invalid fingerprints still rendered `Verified` and produced options; cross-system scope links remained refreshable; corrupt configured identities were ignored by trust decisions.

Repair: migration `0025_authority_read_plans` adds readable projections for bindings, capabilities, scopes, and configured identities. Browser composition builds one fail-closed per-system authority graph from those views. Exact binding fingerprints must be lowercase nonzero 64-hex; identity authority keys are recomputed from the readable binding fingerprint/workspace-root material. Any malformed row disables every option and verified label for only that system. Domain dispatch remains on strict base tables. A two-system, ten-corruption matrix proves healthy sibling cache/detail pages remain readable and `is_refresh_registered` fails closed.

### Finding 2: high, unfiltered readable action history sorts full history

Status: closed.

The readable-state predicate made SQLite choose the state index and a temporary full-history sort before `LIMIT`.

Repair: migration 0025 adds an exact-predicate partial recency index and a forced readable recency view. Deep action cursors split same-timestamp/tiebreak rows from older timestamps rather than using a mixed-direction `OR`. At 20,000 rows both unfiltered and state-filtered probes return 21 rows with 105 validator calls and use indexed `record_created_at < ?` searches.

### Finding 3: medium, relationship filters validate/sort full fanout

Status: closed.

Joining readable child objects forced a temporary sort before `LIMIT`; object-type filtering could inspect the complete fanout. The original corruption marker also used eager `OR`, producing false warnings on healthy rows.

Repair: migration 0025 creates a trigger-maintained `relationship_read_index` with a `(subject, predicate, presence, object_type, object_id)` cursor index. A materialized page is limited before the readable child join, type filters use the projection directly, and lazy `CASE` invokes the warning marker only on invalid containment. Healthy rows produce no warning; cross-system rows remain excluded.

### Finding 4: medium, prefix and deep object cursors re-scan from the prefix start

Status: closed.

Parameterized `LIKE` performed an ordered full-index scan for rare prefixes, uppercase `Z` bounds were wrong under SQLite `NOCASE`, and later pages still began at the prefix lower bound.

Repair: ASCII-NOCASE literal lower/upper bounds drive the display cursor index. Later pages split same-name/object-ID rows from greater-name rows. `Z`/`z` correctness and same-name losslessness are tested; 20,000-row deep probes return 21 rows with 210 validator calls.
