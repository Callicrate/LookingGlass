## Finding 1: medium, documented tool upgrade can switch to unsupported Python

Confidence: high  
Evidence quality: A

Status: closed. README install and force-upgrade commands pin Python 3.12. Distribution verification uses disposable tool and bin directories, installs and force-reinstalls the local wheel with the same pin, asserts the actual interpreter after each operation, and runs the installed CLI. Independent Windows and Ubuntu verification is clear.

The project requires Python `>=3.12,<3.13`, and all release smoke runs in Python 3.12. The README's `uv tool install <wheel>` and `uv tool install --force <new-wheel>` commands omit `--python`.

In an isolated tool directory, the documented install created a Python 3.13.6 environment despite the installed wheel retaining `Requires-Python: >=3.12,<3.13`. Installing with `--python 3.12` correctly created Python 3.12.13, but the documented force-upgrade without `--python` silently replaced that environment with 3.13.6. Basic help still ran, masking the unsupported runtime.

Repair shape: require `--python 3.12` on both install and force-upgrade commands. Extend exact distribution verification with a disposable `UV_TOOL_DIR`/`UV_TOOL_BIN_DIR` probe that installs and force-reinstalls the built wheel, then asserts the tool environment interpreter remains Python 3.12 and the checkout-free command still works.

Verification: run the same probe on Windows and Ubuntu/WSL, preserve no global tool state, and ensure package metadata, wheel behavior, and the documented commands agree.

## Finding 2: medium, timeout does not terminate descendant CLI processes

Confidence: high  
Evidence quality: A

Status: closed. POSIX creates a dedicated session/process group and kills it on normal and exceptional cleanup. Windows creates the CLI suspended, assigns a kill-on-close Job Object, resumes only after assignment, then terminates and waits for the complete Job before releasing snapshot/work directories. Official 0.298 Azure-helper-shaped and synthetic detached/inherited-pipe probes leave no descendant on either platform.

`_terminate_process()` kills only the direct process, then waits without a cleanup bound for the process and stdout/stderr readers. A descendant inheriting those pipes keeps them open after the parent is killed.

With an isolated fake CLI, a 0.1-second timeout returned in 0.16 seconds for a direct parent but took 3.17 seconds on Windows and 3.85 seconds on WSL when the parent spawned a child that inherited stdio and slept for three seconds. A nonterminating descendant can keep the runner, worker heartbeat loop, `serve` shutdown, SQLite close, and runtime lock pending indefinitely.

Repair shape: create one killable process tree for every CLI invocation. Use a process group on POSIX and a kill-on-close Windows Job Object, then bound all process and reader cleanup waits. Normal completion must also close tree ownership so no helper survives the action.

Verification: a real synthetic parent spawning a long-lived child with inherited stdout/stderr and the profile snapshot open must time out and shut down promptly on Windows and POSIX, leave no child, remove the work directory, and allow a later runtime lock owner.

## Finding 3: medium, action lease authority trusts stale caller time

Confidence: high  
Evidence quality: A

Status: closed. `SQLiteStore` owns one injectable UTC clock across intent and action promotion, lease issue/reclaim/currentness/extension, deadlines, originating-scope expiry, guard decisions, satisfaction, terminalization, and action-linked ingestion. `DurableCoordinator` samples `store.authority_time()` for request expiry and refresh policy; caller `now` remains record-only. Future/stale caller reproductions and fresh reclaim are independently clear.

`mark_running`, `_require_live_action_lease`, `heartbeat`, and `complete_action` compare `leased_until` with caller-provided timestamps. An isolated store leased work in an old time window, confirmed wall time was after expiry, then accepted old-window timestamps and persisted the action first as running and then succeeded.

This contradicts the stated store-authoritative local-time lease boundary. A stale or skewed lifecycle caller can terminalize expired work before another worker reclaims it; ordinary worker use of `datetime.now()` narrows but does not enforce the durable port contract.

Repair shape: give `SQLiteStore` one injectable store-owned clock used for lease validity and extension. Caller timestamps may remain recorded event times but cannot establish current authority. Keep deterministic tests through explicit clock injection.

Verification: stale mark-running, heartbeat, attempt, completion, evaluate, and authorize-start calls fail after store-time expiry; a fresh worker can reclaim through the ordinary lease path.

## Finding 4: medium, doctor overstates future Databricks CLI compatibility

Confidence: high  
Evidence quality: A

Status: closed. Doctor full-matches one certified release, rejects every other version before leaf probes, and checks all seven reachable leaf usage/flag contracts. Certification binds file identity, size, nanosecond modification time, and SHA-256 before and after probes. Every mapped dispatch rehashes off the event loop; changed bytes must pass complete recertification before profile snapshot or execution. Official same-path 1.10 replacement was blocked and certified 0.298 reinstall recertified.

Doctor accepts the first version-looking substring at or above 0.298.0; tests explicitly approve 0.299.1 and 1.0.0. It then checks only parent-group help for workspace and Unity Catalog groups. It does not verify the mapped leaf commands, positional shapes, required profile/output/format flags, selected-profile parser semantics, JSON renderer, or iterator pagination that Rookery's authority and completeness depend on.

Current released CLI 1.10.0 source still appears compatible with the relevant parser and renderer behavior, so it is not honestly known-incompatible. It is also not certified by Rookery's exact conformance evidence. The README nevertheless tells operators that every newer version is supported, and doctor marks them healthy.

Repair shape: replace the unbounded minimum with an explicit certified-version set initially containing only installed and fully reviewed 0.298.0. Parse the complete expected version line, reject unknown formats before any other probe, and test each reachable mapped leaf's usage plus `--profile`, `--output`, positional, and applicable `--format` surfaces. Add future releases only after the offline profile/argv/renderer/pagination/cancellation conformance harness passes.

Verification: exact 0.298.0 succeeds; old, suffix-modified, malformed, 0.299, and 1.x fail before leaf probes. Every mapped leaf and required usage/flag token is mandatory. Documentation and installed-wheel smoke state the certified release, not “or newer.”
