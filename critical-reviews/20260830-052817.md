# Rookery critical review: profile snapshot provenance and startup recovery bounds

Reviewed: 2026-08-30 05:28 ET  
Closed: 2026-08-30 06:21 ET
Mode: fresh first-look, technical deep dive, patch-after-review

## Scope

This review covers verified profile authority between check and process execution, startup recovery over retained queues, web/storage validation grammar, and migration/change-safety risks. Three independent read-only passes reviewed current committed source and tests. Explicitly deferred compaction was not treated as a finding by itself.

## Overall assessment

All four original findings and the migration-scale watch item are closed with implementation, regression evidence, independent re-review, and cross-platform validation. Follow-up review widened the profile finding to shared-host workspace selectors and crash-retained snapshots, and found a quadratic disabled-authority aggregate path. Those extensions are also closed.

## Findings

### 1. High — A→B→A profile retargeting can pass both authority checks

Confidence: high  
Evidence quality: A

Status: closed. Host-only profiles retain their v1 digest; profiles with workspace, account, or Azure route selectors use a v2 witness. Each child receives only defaults plus the selected profile from one guarded parse. Per-command locks protect active snapshots, ordinary exit deletes before lock release, and a bounded locked scan before every command recovers snapshots after either hard-exit ordering. Runner and full-worker same-host A→B→A regressions preserve A output only.

Rookery reads profile host A, executes the CLI, then reads A again before accepting output. If another local profile manager changes the same profile A→B before the child reads it and restores B→A before completion, both checks pass although stdout came from B. The worker then normalizes that output into A's cache.

This is not privilege escalation against a malicious same-user; it is a provenance failure under accidental concurrent profile management, contradicting the documented retarget protection.

Repair shape: execute the child against the exact verified bounded config bytes. Publish a protected temporary CLI config snapshot, set the child-only `DATABRICKS_CONFIG_FILE` to that Rookery-owned path, and delete it with the private work directory. Ambient overrides remain stripped.

Verification: deterministic runner and full worker A→B→A tests must prove B output is never accepted under A.

### 2. Medium — startup materializes the entire recoverable queue

Confidence: high  
Evidence quality: A

Status: closed. Startup SQL selects only malformed rows through the same deterministic canonical timestamp validator used by Python. Authority cancellation is set-based, and migration `0021_intent_aggregate_indexes` supplies indexed intent/system aggregate probes. Independent measurements at 10,000, 25,000, and 50,000 affected intents were 0.148 s, 0.423 s, and 0.812 s with linear VM steps and correct mixed-system parents.

Every store open fetches all leased/deferred intent scopes plus leased/running/retry actions, even when almost all timestamps are canonical. Disabled-authority cleanup also fetched action/scope IDs and repaired parents per row. Large future-deferred or orphaned queues therefore scale startup memory/latency before cached pages are exposed.

Repair shape: register a deterministic timestamp validator and select only malformed rows; use set-based authority cancellation and aggregate updates. Keep the disabled/retired authority flag as the immediate dispatch fence.

Verification: large canonical future backlogs must not be materialized, while injected malformed rows and legacy disabled work are still repaired atomically.

### 3. Medium — web query grammar accepts keys/searches that storage rejects

Confidence: high  
Evidence quality: A

Status: closed. Web object and alert keys call the canonical contract validator, whitespace-only name searches fail as client errors, meaningful boundary spaces remain searchable, and composed routes distinguish malformed 400 responses from genuine backend 503 failures.

The web `_CONTRACT_KEY` accepts forms such as `a..b` that canonical storage validation rejects. Whitespace-only dashboard queries also pass presentation validation and fail later. Real routes then report 503/disconnected instead of a client 400.

Repair shape: share the canonical contract-key grammar with web presentation and reject blank/whitespace-only searches before backend invocation.

Verification: composed routes for repeated separators, malformed object types, and whitespace-only search return 400; genuine backend failures remain 503.

### 4. Low — filtered empty-state copy still advertises removed type search

The live object filter is name-prefix-only, but the no-results text still says “Try a different name or type.” Update and render-test the copy.

Status: closed. The live copy says “Try a different name prefix,” with positive and old-copy-negative render assertions.

## Watch item: migration 0018 bootstrap scale

Migration 0018 performs set-based scans/ranking over retained action history in one atomic upgrade. It can require substantial temporary/WAL space on unusually large pre-0018 stores. Existing guidance requires a verified pre-upgrade backup, and failures roll back, but repeated startup can repeat an expensive attempt. Add explicit offline benchmarking and disk-space guidance; promote to a defect if a supported-scale fixture breaches a defined startup/disk budget.

Status: measured and documented without promotion. Exact synthetic 0017-to-current upgrades completed at 250,000 action scopes in 3.22 s for one shared projection key and 6.77 s for distinct targets. The distinct case increased working set by 9.5 MiB and final database size by 226.0 MiB. Integrity and foreign keys remained clean; architecture guidance records the machine, shapes, and rehearsal boundary.
