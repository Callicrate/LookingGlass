## Scope and decision

This pass stress-tests the write-headroom and time-authority repairs when more than one local store object, process attempt, replay, restart, or online backup observes the same SQLite file. It does not reopen the documented single stateful runtime lock without evidence; it checks whether the underlying transactions still fail safely when that composition boundary is bypassed by tests, recovery tooling, or a defective caller.

The decision is patch-after-review. Strict durable receipt ordering must linearize inside SQLite, provenance changes must conflict rather than reconcile silently, leases must retain one owner, capacity checks must not create duplicate actions, migration application must serialize, and backup must remain source-preserving while the live writer commits.
